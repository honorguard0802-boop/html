Page 2: 網頁運作原理 (餐廳隱喻)

解說：前端（用餐區）透過點擊按鈕，呼叫 API（服務生），向後端（廚房）請求資料，最後呈現結果。

實際輸出樣貌 (Live Demo)

目前狀態：等待顧客點餐...

<button id="orderBtn" onclick="placeOrder()">向廚房點餐</button>
<p id="orderStatus">目前狀態：等待顧客點餐...</p>

<script>
function placeOrder() {
    const status = document.getElementById('orderStatus');
    status.innerText = "服務生(API) 傳遞訂單中...";
    setTimeout(() => {
        status.innerText = "🍽️ 餐點已從廚房(後端)送達！";
    }, 1500);
}
</script>

<div id="productCard" class="bg-white text-gray-900 transition-colors">

    <h4>高階抗噪耳機</h4>

<script>
function toggleDarkMode() {
    const card = document.getElementById('productCard');
    // 切換深色與淺色類別
    card.classList.toggle('bg-white');
    card.classList.toggle('bg-gray-900');
    card.classList.toggle('text-gray-900');
    card.classList.toggle('text-white');
}
</script>

Page 8: UI / UX 基礎交集

解說：視覺外觀(UI)很美，但如果點擊範圍太小就是糟糕的體驗(Bad UX)。好的設計必須兼顧美觀與易用性(Good UI+UX)。

實際輸出樣貌 (Live Demo)

❌ Bad UX

✅ Good UI & UX

<!-- Bad UX: 按鈕太小，難以點擊 -->
<button class="text-xs px-2 py-1">結帳</button>

<!-- Good UX: 按鈕寬度飽滿，點擊範圍大，具備 Hover 互動回饋 -->
<button class="w-full h-full text-lg font-bold rounded-lg transition-transform hover:scale-105">
    結帳
</button>
